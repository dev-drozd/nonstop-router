## Что такое NonStop Router?

NonStop Router — это **локальный прокси-сервер**, который располагается между вашими ИИ-агентами написания кода (OpenCode, Claude Code, Codex CLI, Cline, Aider, Continue, Zed, …) и провайдерами моделей. Вы направляете все свои инструменты на единый локальный URL, а шлюз автоматически берет на себя:

- **Отказоустойчивость (Failover)** — при получении ошибок `429`, `5xx`, `401/403` или таймауте запрос автоматически повторяется на следующем ключе или следующей модели.
- **Пул ключей (Key pooling)** — объединение нескольких API-ключей для каждого провайдера и балансировка нагрузки между ними.
- **Один эндпоинт для множества провайдеров** — OpenAI, Anthropic, Google Gemini и любые OpenAI-совместимые API доступны по единому адресу `http://127.0.0.1:4000/v1`.
- **Локальная панель управления** — удобный просмотр и управление провайдерами, моделями, цепочками, логами запросов и статистикой использования.

Шлюз полностью работает на вашей машине, сохраняет все данные в локальной базе данных SQLite, шифрует ключи провайдеров в состоянии покоя и **никогда и никуда не отправляет телеметрию**.

> **Зачем это нужно?** Бесплатные тарифы и общие ключи регулярно исчерпывают лимиты (квоты). NonStop Router превращает ошибку «rate limited, try again later» в незаметное для пользователя переключение на рабочую модель прямо посреди рабочей сессии.

## ✨ Возможности

| | |
|---|---|
| 🔁 **Прозрачный Failover** | Автоматический повтор запросов по цепочке ключей и моделей при ошибках `429`, `5xx`, `401/403`, таймаутах и обрывах потока до первого токена. |
| 🗝️ **Пулы ключей** | Несколько ключей на каждого провайдера со стратегиями `round-robin`, `fill-first` и `least-used`. |
| 🧩 **Мультипротокольность** | Поддержка API OpenAI Chat Completions, Anthropic Messages и OpenAI Responses с двусторонней конвертацией. |
| 🎯 **Цепочки переключения (Chains)** | Настраиваемый порядок моделей в режиме **Priority** (возврат к первой цели при восстановлении) или **Sticky** (фиксация на рабочей цели). |
| 🧠 **Автопоиск моделей** | Получение `/v1/models` от каждого провайдера и обогащение метаданными о контекстном окне, поддержке инструментов, зрении и ценах из [models.dev](https://models.dev). |
| 💸 **Цепочки бесплатных моделей** | Автоматическое построение цепочки в один клик с приоритетом `:free` и локальных моделей, с опциональным резервом на платные модели. |
| 🚦 **Регулятор частоты (Rate governor)** | Скользящее отслеживание RPM для каждого ключа и заблаговременная ротация ключей *до* того, как провайдер вернет `429`. |
| ⚡ **Кэш ответов (Response cache)** | Точный кэш запросов в SQLite (по сообщениям, модели и всем параметрам сэмплинга). Повторные запросы возвращаются за миллисекунды без затрат и расхода квот. |
| 🩺 **Проверка здоровья (Health prober)** | Фоновый опрос для автоматического возврата в строй остывающих и временно недоступных ключей. |
| 🔌 **Сервер MCP** | Предоставление статуса шлюза и списка моделей для агентов с поддержкой Model Context Protocol по адресу `/mcp`. |
| 🔐 **Шифрование ключей** | Ключи провайдеров шифруются алгоритмом AES-256-GCM; через API возвращаются исключительно маскированные значения. |
| 🖥️ **Локальная панель управления** | Интерфейс на React для управления провайдерами, ключами, моделями, цепочками, сниппетами подключения и логами. |
| 🧾 **Настройка инструментов в один клик** | Генерация конфигураций и (опционально) автоматическая запись в файлы настроек OpenCode, Continue и Aider с резервной копией и предпросмотром изменений (diff). |

## 🚀 Быстрый старт

### Требования

- **Node.js 20 или новее** ([скачать](https://nodejs.org))
- Как минимум один API-ключ провайдера (OpenAI, Anthropic, Google, Groq, DeepSeek, OpenRouter, …) — либо локально установленный [Ollama](https://ollama.com) / [LM Studio](https://lmstudio.ai)

### Установка и запуск

```bash
npx nonstop-router
```

Готово. Шлюз запустится на `http://127.0.0.1:4000` и откроет панель управления в вашем браузере.

### Глобальная установка (опционально)

```bash
npm install -g nonstop-router
nonstop-router
```

### Параметры командной строки (CLI)

```text
-p, --port <number>   Порт для запуска (по умолчанию: 4000 или переменная PORT)
    --host <string>   Сетевой интерфейс (по умолчанию: 127.0.0.1)
    --no-open         Не открывать панель управления в браузере автоматически
-v, --version         Вывести версию
-h, --help            Показать справку
```

### Запуск из исходного кода

```bash
git clone https://github.com/skr-electronics-lab/nonstop-router.git
cd nonstop-router
npm install
npm run build
npm start
```

### Docker

```bash
docker build -t nonstop-router .
docker run -d --name nonstop-router \
  -p 4000:4000 \
  -v nonstop-data:/home/nonstop/.nonstop \
  nonstop-router
```

## 🔧 Первоначальная настройка

1. Запустите шлюз (`npx nonstop-router`).
2. Откройте панель управления по адресу **http://127.0.0.1:4000**.
3. Перейдите в **Провайдеры → Добавить провайдера**, выберите готовый пресет (или укажите собственный базовый URL) и введите API-ключ. Модели определятся автоматически.
4. (Опционально) Добавьте дополнительные ключи к провайдеру для включения пула ключей или добавьте других провайдеров.
5. Перейдите в **Цепочки** и настройте порядок переключения — или нажмите **Собрать цепочку бесплатных моделей** для приоритета бесплатных моделей.
6. Перейдите в **Подключение**, скопируйте конфигурационный фрагмент для вашего инструмента (или используйте настройку в один клик) и укажите адрес `http://127.0.0.1:4000/v1` с вашим **ключом шлюза**.

> **Ключ шлюза (Gateway Key)** (начинается с `nsk_live_`) отличается от ключей провайдеров. Он используется для аутентификации *ваших инструментов* на локальном шлюзе и генерируется при первом запуске (см. **Настройки → Локальные API-ключи шлюза**).

## 🧭 Принцип работы

```
   OpenCode / Claude Code / Codex / Cline / Aider
                        │
                        │  model = "auto"
                        ▼
        ┌───────────────────────────────────┐
        │   NonStop Router  :4000           │
        │   (только localhost)              │
        └───────────────────────────────────┘
                        │
             Разрешение цепочки для "auto"
                        │
     ┌───────────────────┼────────────────────┐
     ▼                   ▼                    ▼
   Цель 1              Цель 2               Цель 3
 Провайдер A         Провайдер B          Локальный (Ollama)
 ┌──────────┐        ┌──────────┐         ┌──────────┐
 │ Ключ 1 ✅ │        │ Ключ 1 ✅ │         │ llama3   │
 │ Ключ 2 ⏳ │        │          │         │          │
 └──────────┘        └──────────┘         └──────────┘
     │ 429 / 5xx / таймаут
     └──────────► пробуем Ключ 2 ──► пробуем Цель 2 ──► Цель 3 ──► ✉ понятная ошибка
```

### Триггеры переключения

| Событие | Действие |
|---|---|
| `429 Too Many Requests` | Охлаждение ключа (с учетом заголовка `Retry-After`), переход к следующему ключу. |
| `500 / 502 / 503 / 504` | Охлаждение ключа с экспоненциальной задержкой, переход к следующему ключу. |
| `401 / 403` | Пометка ключа как **недоступен (down)**, переход к следующему ключу. |
| Таймаут соединения / обрыв сокета | Охлаждение ключа, переход к следующему ключу. |
| Обрыв потока до первого токена | Повтор всего запроса на следующей цели в цепочке. |

### Восстановление

- Остывающие ключи возвращаются в пул **автоматически** после завершения времени остывания.
- Фоновый **проверщик здоровья (health prober)** активно тестирует недоступные и остывающие ключи и возвращает их в строй при успешном ответе.
- Учитываются заголовки `Retry-After` и `x-ratelimit-reset-*`; в противном случае применяется экспоненциальная задержка (`30с → 60с → 120с → …`, максимум `300с`).

### Режимы цепочек

- **Priority** (по умолчанию): всегда возвращается к наиболее приоритетной доступной цели, как только она восстанавливается.
- **Sticky**: фиксируется на первой успешно ответившей цели и остается на ней до возникновения ошибки, обеспечивая максимальную непрерывность контекста и кэша.

### Стратегии выбора ключей

*Цепочка* определяет, **какой провайдер** получит запрос; а *стратегия выбора* провайдера
определяет, **какой именно ключ** внутри этого провайдера будет задействован. Любая стратегия пропускает отключенные, недоступные (`down`) или находящиеся на охлаждении (`cooling_down`) ключи и переключается на следующий ключ при ошибке. Разница заключается только в порядке перебора здоровых ключей.

| Стратегия | Как выбирается ключ | Для чего лучше всего | Особенности |
|---|---|---|---|
| **Round Robin** *(по умолчанию)* | Поочередно перебирает список ключей по кругу, по одному запросу на каждый. | Равномерное распределение нагрузки между несколькими ключами одного провайдера. | Может выбрать ключ с малым остатком квоты, когда у других ключей квоты много. |
| **Fill First** | Всегда использует первый доступный ключ до ошибки или охлаждения, затем переходит к следующему. | Максимизация попаданий в **кэш промптов** — один ключ держит «горячий» контекст. | Концентрирует нагрузку на одном ключе, из-за чего его лимит исчерпывается быстрее. |
| **Least Used** | Выбирает ключ с **наименьшим общим числом запросов**, балансируя пул в долгосрочной перспективе. | Смешанные пулы, где ключи имеют разные квоты/возраст и требуется равномерный износ. | Не учитывает давность: только что восстановившийся ключ может выглядеть «неиспользованным» и получить высокую нагрузку. |

**Какая стратегия лучше?** Универсального ответа нет — выбирайте под ваши задачи:

- **Пропускная способность и избежание 429 на множестве ключей → Round Robin.** Детерминированно, честно и равномерно распределяет нагрузку. Именно поэтому она выбрана стратегией по умолчанию.
- **Минимальная задержка и экономия на кэшируемых промптах → Fill First.** Кэширование промптов у большинства провайдеров привязано к конкретному ключу, поэтому фиксация трафика на одном ключе сохраняет кэш теплым.
- **Равномерный износ и разные квоты → Least Used.** Подходит, если ключи добавлялись в разное время или принадлежат разным тарифным планам.

На практике эти различия куда менее критичны, чем сам механизм **отказоустойчивости (failover)** — в этом и заключается главная суть NonStop Router. Все три стратегии моментально отправляют сбойный ключ на охлаждение и мгновенно пробуют следующий. Рекомендуется начинать с **Round Robin** и переключаться на **Fill First** только если вам целенаправленно нужна локальность кэша на одном ключе.

> На странице «Схема маршрутизации» отображается активная стратегия каждого провайдера, а в панели ключей выводятся счетчики токенов и запросов в реальном времени.

## 📚 Справочник API

Для всех эндпоинтов шлюза требуется передавать **ключ шлюза** через заголовок `Authorization: Bearer <ключ>` или `x-api-key`.

| Метод | Эндпоинт | Описание |
|---|---|---|
| `POST` | `/v1/chat/completions` | OpenAI Chat Completions (потоковый и непотоковый режимы). |
| `POST` | `/v1/messages` | Anthropic Messages API (для Claude Code). |
| `POST` | `/v1/responses` | OpenAI Responses API (для Codex CLI). |
| `GET` | `/v1/models` | Список цепочек, активных моделей и универсальных псевдонимов. |
| `POST` | `/mcp` | Эндпоинт Model Context Protocol (JSON-RPC). |

Укажите `model: "auto"` для использования цепочки переключения по умолчанию, либо имя конкретной цепочки или модели.

```bash
curl http://127.0.0.1:4000/v1/chat/completions \
  -H "Authorization: Bearer $NONSTOP_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Привет!"}]}'
```

API управления (`/api/*`) обеспечивает работу панели управления и требует админский токен (автоматически внедряется на странице веб-интерфейса).

## 🔒 Безопасность

- **Только localhost по умолчанию.** Шлюз слушает адрес `127.0.0.1`. Включение доступа по локальной сети (LAN) — это явная, отдельная опция с предупреждением в Настройках.
- **Шифрование в состоянии покоя.** Ключи провайдеров шифруются алгоритмом **AES-256-GCM**. 256-битный мастер-ключ хранится в `~/.nonstop/master.key` с ограниченными правами доступа.
- **Маскирование ключей.** Ключи провайдеров и ключи шлюза отображаются в маскированном виде (`sk-…1234`) и никогда не возвращаются в открытом виде через API списков или деталей.
- **Раздельная аутентификация.** Для `/api/*` требуется токен администратора; для `/v1/*` — ключ шлюза. Проверка токенов выполняется с защитой от атак по времени (constant-time).
- **Никакой телеметрии.** Никакие данные о вашем использовании не покидают компьютер. Единственные исходящие сетевые вызовы — это настроенные вами обращения к провайдерам плюс запрос метаданных моделей с `models.dev` (кэшируется локально на 24 часа и корректно пропускается при работе офлайн).

> **Никогда не публикуйте порт шлюза напрямую в публичный интернет.** Он спроектирован для локального использования или доверенной сети. При необходимости сетевого доступа используйте обратный прокси-сервер с TLS и собственной аутентификацией.

## ⚙️ Конфигурация

Параметры настраиваются в панели управления (**Настройки**) и сохраняются в базе данных SQLite по пути `~/.nonstop/router.sqlite`. Основные параметры:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `defaultRequestTimeoutMs` | `60000` | Таймаут одной попытки запроса к апстриму до переключения. |
| `cooldownBaseMs` / `cooldownMaxMs` | `30000` / `300000` | Границы экспоненциальной задержки для сбойных ключей. |
| `healthProbeIntervalMs` | `30000` | Интервал фоновой проверки недоступных ключей. |
| `enableCache` / `cacheTtlMs` / `cacheMaxEntries` | `true` / `24h` / `2000` | Точный кэш ответов на повторяющиеся промпты. |
| `enableRateGovernor` / `rateGovernorRpm` | `true` / `25` | Скользящий лимит RPM на один ключ. |
| `enablePromptOptimizer` | `false` | Оптимизация промптов с потерями (по умолчанию выключена). |
| `storePayloads` | `false` | Сохранение тел запросов и ответов в логах (чувствительно к приватности). |
| `allowLan` | `false` | Привязка к `0.0.0.0` вместо `127.0.0.1`. |
| `chainAutoPolicy` | `free_only` | Политика по умолчанию для автоматически собираемых цепочек. |

### Расположение данных

| Путь | Содержимое |
|---|---|
| `~/.nonstop/router.sqlite` | Провайдеры, ключи, модели, цепочки, логи, настройки. |
| `~/.nonstop/master.key` | Мастер-ключ AES-256 для шифрования ключей провайдеров. |

Для резервного копирования достаточно сохранить каталог `~/.nonstop/`.

## ❓ Часто задаваемые вопросы (FAQ)

<details>
<summary><strong>Отправляются ли мои данные куда-либо?</strong></summary>

Нет. Шлюз работает исключительно локально и сохраняет все данные в `~/.nonstop`. Помимо настроенных вами провайдеров, единственным исходящим запросом является опциональная загрузка метаданных моделей с `models.dev` (кэшируется на 24 часа и корректно работает офлайн).
</details>

<details>
<summary><strong>В чем разница между ключом шлюза и ключами провайдеров?</strong></summary>

Ваши **ключи провайдеров** (OpenAI, Anthropic, …) хранятся в зашифрованном виде и используются шлюзом для отправки запросов. **Ключ шлюза** (`nsk_live_…`) используется вашими локальными программами и редакторами для подключения к самому NonStop Router. Ключи никогда не покидают ваше устройство.
</details>

<details>
<summary><strong>Возможно ли переключение посреди потоковой передачи (streaming)?</strong></summary>

Если апстрим оборвался **до первого токена**, шлюз прозрачно повторяет запрос на следующей цели. После того как первые токены уже были переданы клиенту, переключение на другую модель без повреждения ответа невозможно — включите опцию **«Перезапуск при сбое посреди потока»** в Настройках, если хотите, чтобы в этом случае запрос перезапускался с нуля на резервной модели (с отбрасыванием неполного ответа).
</details>

<details>
<summary><strong>Работает ли шлюз офлайн / с локальными моделями?</strong></summary>

Да. Подключите Ollama (`http://127.0.0.1:11434/v1`) или LM Studio (`http://127.0.0.1:1234/v1`). Локальные модели автоматически ставятся в конец цепочек, выступая в роли гарантированной страховки.
</details>

<details>
<summary><strong>Зачем для npm install нужен компилятор C++?</strong></summary>

Библиотека `better-sqlite3` является нативным Node.js-модулем. Для популярных платформ загружаются готовые бинарные файлы; в остальных случаях используется компилятор C++. В Docker-образе все зависимости сборки уже установлены.
</details>
